1 - через датасет карьерных путей рф мы должны понимать в какие следующие должности может перерости сотрудник
2 - найти может датасет еще каких-то курсов и тд. и предлагать их. то есть если карьерный путь говорит, что из такой должности человек может перерости в такую, то еще должны предлагаться и курсы подходящие для обучения этому
3 - про формирование новой отдела. допустим в фирме планируется формироваться новый отдел. и мы должны как бы создать этот отдел в менюшке и нам должно показываться, что вот этот сотрудник может перерости в эту должность (по карьерным путям смотрим и курсы предлагаемые тоже там пишутся). а если есть должность откуда человек туда перерости не может или что-то такое, то там должна писаться вилка зарплатная такого сотрудника по данным хх ру, судя по вакансиям и резюме и так же по возможности еще анализ резюме, для того чтобы доставать оттуда основные знания таких специалистов

# COMPASS-HR (локальная реализация): данные → ML → HR-портал

## 1) Что именно используется в проекте и за что отвечает

### Портал / интерфейс / хранение “HR-данных”
1. **Frappe Framework** — платформа (backend + web UI) для сборки бизнес-приложений: формы, списки, роли/права, отчёты, фоновые задачи, встроенный REST API для сущностей (DocTypes).
2. **ERPNext** — готовое приложение на Frappe (в т.ч. проекты/задачи/пользователи/структура), используется как “базовый портал”.
3. **Frappe HRMS** — HR-приложение на Frappe/ERPNext: сотрудники, оргструктура, HR-объекты. Используется как “HR-часть портала”.

> Важно: обычно это **одна локальная установка** (один веб-портал в браузере), внутри которой установлены “apps”: ERPNext + HRMS на платформе Frappe.

### Внешние данные
4. **Датасет карьерных траекторий РФ (2015–2023)** — для моделирования переходов “должность → следующая должность”.
   - Zenodo (страница с файлами и Codebook): https://zenodo.org/records/12727876
   - DOI: 10.5281/zenodo.12727876
5. **hh.ru API** — для получения вакансий, требований, зарплатных вилок; используется для:
   - расчёта “стоимости” внешнего найма (salary range / salary model),
   - извлечения навыков из текста вакансий,
   - пополнения справочника навыков и профилей ролей.
   - API entrypoint: https://api.hh.ru/
   - OpenAPI (ReDoc): https://api.hh.ru/openapi/redoc

### Данные по курсам / обучению
6. **Stepik API** — официальный REST API для формирования локального каталога курсов (описания, навыки/темы, ссылки).
   - Docs: https://stepik.org/api/docs/
7. **(Опционально) датасеты курсов (Kaggle и др.)** — использовать только при проверенной лицензии/источнике; цель — быстро расширить каталог.  
   - Пример поиска (не источник истины): https://www.kaggle.com/search?q=courses+dataset

### ML/AI слой (локально)
8. **Jupyter Notebook** — исследовательские ноутбуки для EDA/прототипирования/метрик; “боевой” код фиксируется в Python-модулях.
9. **ML-сервис (FastAPI)** — отдельный сервис (localhost), который:
   - обучает/загружает модели,
   - выполняет инференс,
   - отдаёт рекомендации порталу (ERPNext/HRMS),
   - пишет результаты обратно в DocTypes через Frappe API (или вызывается из Frappe серверным кодом).

## 2) Целевые функции модуля (что должно работать в “нормальной версии”)

### Функция A — прогноз карьерных переходов (внутренняя мобильность)
- По текущей роли/стажу/профилю навыков выдаётся:
  - топ-N вероятных следующих ролей,
  - объяснение (влияющие факторы/похожие траектории/частоты переходов),
  - ограничения/условия (например, требуемые навыки, типичный стаж до перехода).

### Функция B — рекомендации обучения под карьерную цель
- Для выбранной целевой роли вычисляется skill-gap.
- Для каждого “пробела” подбираются курсы/модули обучения.
- Результат: персональный план обучения + ссылки на курсы + причина рекомендации.

### Функция C — планирование нового отдела (внутренние кандидаты + upskilling + внешний найм)
- Создаётся “профиль отдела”: роли, количество, требования, сроки.
- Для каждой роли:
  - предлагаются внутренние кандидаты (которые могут “дорасти” по траекториям и навыкам),
  - формируется план upskilling (курсы) для доведения до роли,
  - при отсутствии внутренних кандидатов оценивается внешний найм:
    - зарплатная вилка по данным hh.ru,
    - ключевые навыки роли (из вакансий и/или локальных резюме),
    - ориентировочные требования.

## 3) Архитектура (без отдельного MVP-круга)

### 3.1. Модели и алгоритмы (ядро)
1. **Модель карьерных траекторий (sequence model)**
   - Цель: предсказывать распределение по “следующим ролям” и/или “k шагов вперёд”.
   - Подход: нейросетевая модель последовательностей (Transformer/GRU/LSTM) по событиям карьеры.
   - Дополнительно: граф переходов/матрица переходов как интерпретируемый слой и для sanity-check (не отдельный “второй круг”, а часть решения для объяснимости).

2. **Извлечение навыков и семантика (NLP слой)**
   - Цель: приводить тексты (вакансии, резюме, описания курсов, описания ролей) к единому “пространству навыков”.
   - Подход:
     - эмбеддинги (ruE5/ruBERT-подобные модели) для семантического поиска и сопоставления,
     - извлечение навыков (NER/Keyphrase extraction + нормализация) → маппинг в справочник Skill.
   - Результат: единый Skill-граф/таксономия + веса/уровни владения.

3. **Оценка зарплаты / стоимости найма (табличная ML-модель)**
   - Цель: прогноз “salary range” для роли/региона/стека/опыта по данным hh.ru.
   - Подход: CatBoost-регрессия (или аналогичный бустинг) + расчёт доверительных интервалов/квантилей.
   - Результат: для TeamPlan выдаётся оценка бюджета внешнего найма.

4. **Сборка рекомендаций (ранжирование + оптимизация)**
   - Для сотрудника: ранжирование целевых ролей по вероятности перехода + совместимости навыков.
   - Для курсов: ранжирование по покрытию skill-gap (семантическая близость + “покрытие навыков”).
   - Для отдела: задача назначения (assignment) “роль → внутренний кандидат / upskill / внешний найм” с минимизацией стоимости и учётом ограничений (сроки, занятость, критичность).

### 3.2. Сервисы (локально)
- **ERPNext + HRMS (Frappe)**: UI/хранилище/права/процессы.
- **FastAPI ML-service**: обучение/инференс/рекомендации/агрегация.
- **PostgreSQL** (рекомендуется) или MariaDB (внутри Frappe) + отдельная БД для ML (по необходимости).
- **Vector storage** (рекомендуется): pgvector или Qdrant для эмбеддингов (вакансии/курсы/резюме/роли).

### Этап 3 — Пайплайны данных (скачивание → нормализация → хранилище)
#### 3.1. Карьерные траектории РФ (Zenodo)
1. Скачать архивы и Codebook (см. ссылки выше).
2. Реализовать ETL:
   - стандартизация названий должностей (нормализация/лемматизация/словари),
   - маппинг должностей в внутренний справочник ролей,
   - формирование последовательностей “роль → роль” с временными метками и контекстом.
3. Создать train/val/test сплиты по времени (например, 2015–2021 train, 2022 val, 2023 test).

#### 3.2. hh.ru (вакансии)
1. Реализовать сборщик вакансий (cache-first):
   - вход: роль/регион/опыт/стек (ключевые слова)
   - выход: JSON вакансий + parsed features
2. Реализовать extractor:
   - зарплата from/to, валюта, регион, опыт, график,
   - текст требований → навыки/эмбеддинги,
   - сохранение в локальное хранилище (Postgres/Parquet).

#### 3.3. Курсы (Stepik)
1. Реализовать сбор каталога:
   - поиск по ключевым словам/тегам,
   - сохранение title/description/url/метаданных.
2. Прогнать через NLP слой:
   - извлечение навыков из описания,
   - эмбеддинги в vector store.

**Результат:** единый локальный “даталейк” + нормализованные справочники (Roles/Skills/Courses).

### Этап 4 — Обучение моделей (сразу рабочая версия)
#### 4.1. Модель карьерных траекторий
1. Подготовить события карьеры как последовательность токенов/признаков:
   - role_id, отрасль/тип компании (если есть), регион, длительность, (опционально) образование.
2. Обучить sequence-модель:
   - задача next-role prediction (multi-class)
   - метрики: hit@k, MRR, nDCG, calibration.
3. Добавить объяснимость:
   - похожие траектории (nearest neighbors),
   - частоты переходов (граф) как “reason codes”.

#### 4.2. NLP слой навыков (вакансии/резюме/курсы/роли)
1. Поднять эмбеддинг-модель (ruE5/ruBERT-подобная) и сохранить эмбеддинги в vector store.
2. Реализовать извлечение навыков:
   - keyphrase/NER → нормализация → маппинг в Skill.
3. Метрики качества:
   - ручная валидация на 50–100 примерах,
   - precision/recall по “gold” разметке (маленькой, но честной).

#### 4.3. Модель зарплаты (CatBoost)
1. Сформировать датасет из hh вакансий:
   - признаки: регион, роль, опыт, стек (из текста), тип занятости и т.п.
2. Обучить модель:
   - цель: salary_mid или квантильные модели (если реализуется).
3. Проверить метрики:
   - MAE/MAPE, ошибки по регионам/ролям, устойчивость.

**Результат:** обученные модели + сохранённые артефакты (weights/encoders/indexes).

### Этап 5 — ML-сервис (FastAPI) и контракт интеграции
1. Реализовать сервис FastAPI (localhost), который:
   - загружает модели/индексы,
   - принимает входные данные из портала,
   - возвращает JSON-результаты для сохранения в DocTypes.

Рекомендуемые эндпоинты:
- `POST /career/predict-next`  
  вход: employee_profile → выход: top_roles[] + explanations
- `POST /skills/extract`  
  вход: text/resume/vacancy → выход: skills[] (normalized)
- `POST /learning/recommend`  
  вход: employee_skills + target_role → выход: gap + courses[]
- `POST /team/plan`  
  вход: target_roles + employees + constraints → выход: internal/upskill/external + costs
- `GET /market/salary-range?role=&region=&level=`  
  выход: range + confidence

2. Зафиксировать формат идентификаторов:
- `employee_id`, `role_id`, `skill_id`, `course_id` — единый формат во всех сервисах.
3. Добавить локальный cache:
- результаты hh/Stepik запросов,
- эмбеддинги и индексы.

**Результат:** единый “мозг” модуля с чётким API-контрактом.

### Этап 8 — Валидация и демонстрационные сценарии (под магистерскую)
1. Сценарий “карьерный план сотрудника”:

3. Оценка качества:
- offline метрики (hit@k, MRR, MAE),
- бизнес-метрики (готовые KPI, рассчитанные на синтетике/исторических данных).
